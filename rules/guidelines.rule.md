# 개발 및 코딩 가이드라인 (Coding Guidelines Rule)

에이전트는 대상 프로젝트의 소스코드를 편집하거나 생성할 때 다음 규칙을 준수해야 합니다.

## 핵심 코딩 수칙
1. **한국어 주석 필수**:
   * 소스코드 내의 모든 설명 주석(함수, 클래스, 복잡한 비즈니스 로직에 대한 설명 등)은 반드시 **한국어**로 작성해야 합니다.
2. **코드 스타일 가이드**:
   * 각 프로젝트의 린터(`eslint`, `pylint` 등) 설정에 맞게 포맷팅을 자동으로 준수합니다.
   * 복잡한 중첩 루프 작성을 지양하고 기능별로 잘게 쪼개어 가독성을 높입니다.
3. **기존 주석 보존**:
   * 사용자가 사전에 명시하지 않은 한, 기존 소스코드에 존재하는 유용한 주석과 문서(docstring)는 함부로 삭제하거나 변형하지 않고 원형을 유지해야 합니다.

## 클린코드 핵심 원칙 (Clean Code Principles)
1. **의도가 명확한 네이밍(Meaningful Names)**:
   * 모든 변수, 함수, 클래스 이름은 그 자체로 존재 목적과 쓰임새를 명확히 설명할 수 있도록 지어야 합니다.
   * 매직 넘버나 불명확한 단일 문자 변수(예: `d`, `temp`, `x`) 사용을 지양하고, 구체적인 이름(예: `elapsedTimeInDays`)을 사용하십시오.
2. **단일 책임을 갖는 함수(Single Responsibility)**:
   * 하나의 함수는 오직 한 가지 일만 수행하도록 최대한 작게 분할해 작성해야 합니다.
   * 함수 내 중첩 단계(Indent)는 가급적 1~2단계를 초과하지 않도록 쪼개고, 함수 길이를 간결하게 유지하십시오.
3. **예측 가능한 부수 효과 방지(No Side Effects)**:
   * 입력받은 아규먼트나 전역 상태를 명시적인 동의 없이 임의로 변경하지 않고, 예측 가능하도록 값의 불변성(Immutability)을 존중하여 설계하십시오.
4. **견고한 예외 처리(Error Handling)**:
   * 함수나 메소드에서 비정상적인 상황이 발생했을 때 `null` 또는 임의의 에러 코드를 리턴하기보다, 명시적이고 구체적인 예외(Exception)를 던져 호출자 측에서 안전하게 복구할 수 있도록 하십시오.
5. **코드 중복 최소화(DRY - Don't Repeat Yourself)**:
   * 비슷한 논리의 비즈니스 구조나 설정 코드가 중복되어 발견될 경우, 적절히 공통 컴포넌트나 함수로 리팩토링하여 단일 원천 정보(Single Source of Truth)를 유지하십시오.
